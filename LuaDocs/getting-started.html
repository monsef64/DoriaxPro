Getting started with Lua in Doriax Pro

Build your first playable scene, wire input, and publish Windows & Linux x64 builds straight from CI.

Installation

Option A — Download a release

Head to Releases and grab DoriaxPro-*-windows-x64.zip or -linux-x64.tar.gz. Unzip and run doriax-editor.

Windows • Powershell
Expand-Archive DoriaxPro-v1.0.0-windows-x64.zip .
.\dist\bin\doriax-editor.exe

Option B — Build from source

Requires CMake 3.27+, Ninja, Python 3. Linux needs the X11/Wayland dev packages from the README.

Linux x64
sudo apt-get install build-essential cmake ninja-build pkg-config python3 \
  libx11-dev libxcursor-dev libxi-dev libxrandr-dev libgl1-mesa-dev \
  libwayland-dev wayland-protocols libdbus-1-dev libcurl4-openssl-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target doriax-editor
./build/doriax-editor
Windows x64 (VS 2022)
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --target doriax-editor doriax-editor-cmd
.\build\Release\doriax-editor.exe

Project structure

Every game lives under engine/project/ (or any folder you point the editor at). The two folders the runtime preloads are:

PathWhat goes there
project/lua/Your Lua scripts (main.lua is the entry point). Hot-reloaded in Play.
project/assets/Textures, models, sounds, fonts — referenced by name inside Lua or scenes.
project/scenes/Saved editor scenes (YAML). You can also build scenes purely in Lua.
engine/project/Default demo project (lua/main.lua prints “lua file”).
project tree
DoriaxPro/
├─ engine/project/
│  ├─ lua/main.lua
│  └─ assets/doriax.png
├─ editor/            # C++ editor
├─ LuaDocs/           # you are here — HTML docs
├─ .github/workflows/build-windows-linux.yml
└─ .github/workflows/release.yml

Lifecycle & callbacks

The engine calls into your Lua via Engine hooks. Assign them in main.lua — they survive scene changes.

HookWhenTypical use
Engine.onViewLoadedViewport is ready, before first frameCreate scenes, set canvas, preload
Engine.onUpdateEvery frame (variable dt)Game logic, input polling, tweens
Engine.onFixedUpdateFixed timestep (physics)Apply forces, move kinematic bodies
Engine.onDrawAfter scene culling, before presentDebug draws, gizmos
Engine.onPostUpdateAfter all subsystemsFollow cameras, finalize
Engine.onKeyDown / onKeyUp / onCharInputKeyboard eventsShortcuts, text input
Engine.onGamepad*Gamepad connect/axis/buttonLocal multiplayer
lua/main.lua — minimal lifecycle
-- main.lua — runs once when the project loads
print("lua file")

Engine.onViewLoaded = function()
  -- runs once the window & GL/Vulkan context exist
  Engine.canvasWidth = 1280
  Engine.scalingMode = Scaling.FITWIDTH
  Log:info("Viewport ready")
end

Engine.onUpdate = function()
  -- called ~60Hz, dt in Engine.deltatime
  -- local dt = Engine.deltatime
end

Scene flow

Two ways to work — pick what fits:

A. Author in the editor

Place objects visually, then drive them from Lua by name or handle.

lua
-- find an editor-placed object
local hero = Engine:getScene():findObject("Hero")
-- or by EntityHandle
local h = EntityHandle.new(scene, "Hero")

B. Build purely in Lua

No saved scene needed — create everything at runtime.

lua — scene from code
local scene = Scene.new()
local cam = Camera.new(scene)
cam.position = Vector3.new(0, 4, 8)
cam:setPerspective(60, 0.1, 100)
cam:activate()

local sun = Light.new(scene)
sun.color = Vector3.new(1, 1, 0.95)
sun.intensity = 1.2
sun:setDirection(-0.5, -1, -0.3)

local box = Mesh.new(scene)
box:setMesh("cube")
box.position = Vector3.new(0, 0.5, 0)

Engine:setScene(scene)

Switch scenes at any time:

lua
-- registered scenes (by id or name)
SceneManager.loadScene("MainMenu")
SceneManager.addChildScene("HUD")
SceneManager.preloadScene("Level2") -- async, check progress via getPreloadProgress()

Input & UI

Poll or subscribe — both work. Input respects Engine.ignoreEventsHandledByUI so UI eats clicks first.

lua — input
-- polling (inside onUpdate)
if Input:isMouseButtonDown(0) then
  local ray = Camera.main:screenToRay(Input.mousePosition)
  -- raycast, place objects…
end

-- events
Engine.onKeyDown = function(key, scancode) 
  if key == Key.ESCAPE then Engine:pauseGameEvents(true) end
end

-- mouse wheel / touch
-- Input.mousePosition -> Vector2, Input.isTouch -> bool

UI is entity-based: Panel, Button, Text, Image, ProgressBar — each has an anchor/pivot system via AnchorPreset / PivotPreset.

Tips & next steps

Use the editor’s code assist

generate_api_suggestions.py → engine_api_suggestions.h powers completion for every binding. Rebuild after adding C++ bindings.

Prefer handles for safety

EntityHandle stays valid across destroy/create. Cache the handle, not the raw pointer.

Profile with ResourceProgress

ResourceProgress.hasActiveBuilds() tells you when threaded texture/model builds are still running — gate your loading screen on it.

Ship via CI

Tag v1.0.0 → Actions builds windows-x64 + linux-x64 → attaches to the release automatically. No need to build locally for players.
